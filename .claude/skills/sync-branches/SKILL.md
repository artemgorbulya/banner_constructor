---
description: "Синхронізує локальний репозиторій з GitHub: оновлює всі гілки, підтягує нові з remote, видаляє локальні гілки яких вже немає на remote."
---

Мета: після виконання локальний репозиторій — точна копія `origin` (усі актуальні гілки з усіма комітами), без застарілих локальних гілок і посилань.

Кроки:

1. Перевір незакомічені зміни: `git status --porcelain`. Якщо є — зупинись, повідом користувачу і попроси закомітити або застешити (`git stash -u`) вручну. Не роби цього сам без дозволу.

2. Онови дані з усіх remote і одразу прибери застарілі remote-tracking посилання (для гілок вже видалених на GitHub): `git fetch --all --prune`.

3. Визнач дефолтну гілку репозиторію: `git remote show origin | grep 'HEAD branch'`.

4. Виведи `git branch -vv` і розбий локальні гілки на категорії:
   - **[gone]** — upstream видалено на GitHub → кандидат на локальне видалення.
   - **behind** — remote попереду локальної, без розбіжностей → можна безпечно оновити (fast-forward).
   - **ahead / diverged** — є локальні коміти яких немає на remote → НЕ чіпай автоматично, лише повідом користувача.
   - **up to date** — нічого не робити.

5. Для гілок **[gone]**:
   - Якщо це поточна гілка — спочатку перейди на дефолтну гілку (`git checkout <default>`).
   - Спробуй `git branch -d <branch>` (safe delete, спрацює лише якщо гілку вже змержено).
   - Якщо `-d` відмовляє через незамерджені коміти — НЕ видаляй примусово (`-D`) автоматично. Зістав список таких гілок і явно запитай користувача, чи видалити кожну примусово.

6. Для гілок **behind** (не diverged) онови без checkout: `git fetch origin <branch>:<branch>`. Для поточної гілки замість цього використай `git pull --ff-only`.

7. Для гілок що є на remote, але відсутні локально — створи локальні tracking-гілки: `git branch <branch> origin/<branch>` для кожної.

8. Наприкінці виведи підсумок: скільки гілок оновлено (ff), скільки видалено, скільки створено нових, і окремо перелічи diverged-гілки що потребують ручного рішення (якщо такі є).

Ніколи не використовуй `git reset --hard`, примусове `git branch -D` чи `git push --force` без явного підтвердження користувача для кожного конкретного випадку.
